# Git과 GitHub 수동 작업 능력 회복 과정

## 목표

2주 동안 주 5회, 회당 30분씩 총 10회 연습해 일상적인 Git과 GitHub 작업을 Codex의 정답 명령 없이 수행한다. 기존 학습 노트는 첫 시도 전에 보지 않고, 막혔을 때만 확인한다.

## 한 회차 진행 방법

1. 5분 동안 관련 용어 세 개와 이전 회차의 실수를 기억해서 설명한다.
2. 20분 동안 현재 상태, 선택할 명령, 예상 결과를 말한 뒤 직접 실습한다.
3. 5분 동안 실제 결과와 예상이 달랐던 부분을 설명하고 학습 일지에 짧게 기록한다.

명령을 실행했다는 사실만으로 완료하지 않는다. 상태 변화를 설명하고 아래 완료 기준을 충족한 회차만 체크한다.

## 준비 실습: worktree 분리

- 기본 worktree는 `main`을 유지하고 별도 폴더에 작업 브랜치를 연결한다.
- 새 worktree를 기존 저장소 내부에 만들면 부모 저장소가 전체 폴더를 추적되지 않은 파일로 볼 수 있으므로 저장소 밖의 경로를 사용한다.
- worktree를 제거할 때는 폴더를 직접 삭제하지 않고 Git의 worktree 제거 기능을 사용한다.

## 1주 차: 일상 작업 흐름

- [ ] **1회차 — 상태와 diff 읽기**: Working Directory, Staging Area, HEAD의 차이를 실제 출력으로 구분하고 다음 행동을 설명한다.
- [ ] **2회차 — 선택적 스테이징과 커밋**: 여러 변경 중 필요한 것만 커밋하고 잘못 올린 변경을 파일 내용 손실 없이 스테이징에서 내린다.
- [ ] **3회차 — 브랜치와 히스토리**: 작업 브랜치를 만들고 전환하며 분기와 합류 결과를 그래프로 설명한다.
- [ ] **4회차 — 원격 동기화**: fetch와 pull의 차이를 설명하고 ahead, behind, divergence 상태에 맞는 안전한 행동을 선택한다.
- [x] **5회차 — push와 Pull Request**: 작업 브랜치에 upstream을 설정하고 PR 생성, CI 확인, 머지, 로컬 정리까지 직접 수행한다.

## 2주 차: 중단과 복구

- [ ] **6회차 — 작업 중단과 잘못된 브랜치**: 미완성 변경을 안전하게 보관하고 잘못된 브랜치의 커밋을 올바른 브랜치로 옮긴다.
- [ ] **7회차 — merge conflict**: 충돌 파일과 상태를 읽고 해결한 뒤 계속 진행하거나 안전하게 중단한다.
- [ ] **8회차 — 되돌리기와 복구**: restore, reset, revert 중 상황에 맞는 방법을 선택하고 reflog로 잃어버린 커밋을 찾는다.
- [ ] **9회차 — 변경 원인 조사**: log 필터, blame, bisect를 사용해 변경 시점과 버그가 시작된 커밋을 찾는다.
- [ ] **10회차 — 종합 실습**: 실제 PR 작업과 임시 저장소의 복구 문제를 직접 명령 힌트 없이 완료한다.

## 완료 기준

- 10회차를 모두 직접 수행한다.
- 종합 실습에서 상태 확인, 브랜치 생성, 선택적 커밋, 원격 게시, 충돌 또는 실수 복구를 명령 힌트 없이 처리한다.
- 각 단계가 Working Directory, Staging Area, 로컬 저장소, 원격 저장소 중 어디를 바꾸는지 설명한다.
